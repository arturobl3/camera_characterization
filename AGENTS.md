# AGENTS.md

## Commands

- Setup: `uv sync` (Python >=3.11; creates `.venv`)
- Run: `uv run camchar ...` or `uv run python -m camchar ...` (equivalent)
- The CLI is a **typer** app (`camchar/cli.py`): rich, colored help and output (colors auto-disable when piped). Helpers in cli.py take explicit kwargs — no argparse Namespace. Exit codes are raised via `typer.Exit` (warmup 130 on Ctrl+C/1 on abort/1 when the backend has no temperature API; stability check 1 when unstable). `--vendor` (playerone | basler | thorlabs) is a required option on the four acquisition commands; `analyze` is offline and has none.
- Verify without hardware: `uv run camchar --help`; `uv run camchar analyze --data data`
- Lint: `uv run ruff check .` — Format: `uv run ruff format .` (ruff is a dev dependency; `vendor/` is excluded — never lint/format the vendored SDK wrapper)
- Test: `uv run pytest` (pytest is a dev dependency; `[tool.pytest.ini_options]` in pyproject.toml, `testpaths = ["tests"]`). Tests fall into two groups: CLI exit-code tests with mocked backends (`tests/test_cli.py`, Typer CliRunner — exit 1 unstable, 0 stable, 130 Ctrl+C, 1 abort, 2 bad exposures/missing vendor) and pure-function unit tests (`tests/test_analyze.py`, `tests/test_io_utils.py`) that lock in the EMVA fit semantics (Eq. 50 zero-intercept K, dV>0 selection, 70%-of-mu_sat cap, dark-variance extrapolation, degenerate-guard None) and the filename/metadata conventions (stem_for round-trip, camera_dir_name). No typecheck is configured. Don't add other test frameworks.

## Hardware dependence

- `get-dark-frames` / `get-flat-frames` / `warmup-sensor` / `source-stability-check` require a physically connected Player One, Basler, or Thorlabs camera (direct USB, no hub). Don't run acquisition commands as a code check.
- `analyze` is offline: reads `<camera>/dark/` + `<camera>/flat/` via their `metadata.json`; writes plots to `outputs/<vendor>_<model>_(<sensor>)/` (CWD, gitignored) via `camchar/plots.py` (matplotlib, Agg backend).
- The backend retries camera enumeration for up to 60 s at `open()` by design (USB enumeration is flaky); don't shorten or remove this.
- SPECIM IQ per-band analysis (`camchar/band_analyze.py` + `camchar/specim.py`) reads the ENVI export under `data/SPECIM_IQ/` (~48 GB; full run ~30 s). A quick check: `uv run camchar analyze --data data/SPECIM_IQ --help` parses; for a fast functional smoke test symlink 3 acquisitions per exposure into a scratch dir and analyze that.

## Player One SDK — deliberate workarounds, do not "fix"

- The vendored wrapper `vendor/playerone/py/pyPOACamera.py` has an ABI bug: `POASetConfig`/`POAGetConfig` pass `c_int` where the C API expects an 8-byte `POAConfigValue` union, silently corrupting config writes. `camchar/backends/playerone.py` bypasses the wrapper and calls the DLL directly with a ctypes `Union`. Never route config reads/writes back through the wrapper.
- `PlayerOneBackend.close()` is intentionally a no-op: `CloseCamera()` wedges the device on macOS until physically replugged. Process exit is the cleanup.
- Exposure uses config 31 (`POA_EXP`, seconds, float) with fallback to config 0 (`POA_EXPOSURE`, µs, int).
- SDK binaries are OS-specific and must be placed in `vendor/playerone/lib/` (loading is platform-aware in the wrapper). Windows: `PlayerOneCamera.dll` + WinUSB driver. macOS: dylib(s) + Homebrew libusb patched in via `install_name_tool` (see README).

## Basler backend (pypylon) — conventions

- `camchar/backends/basler.py` drives Basler cameras via pypylon (wheel bundles the pylon runtime; if enumeration fails, the pylon Software Suite USB3 driver is missing). `--vendor basler` (required) selects it; `--gain` is float dB (Player One keeps its int coercion).
- Grabs `PixelFormat Mono12` (unpacked) with a per-frame software trigger (`TriggerMode=FrameStart/Software`): free-run buffers would be stale after an exposure change. Frames are `<<4` to DN16 at the backend, matching the playerone path so analyze.py constants/fits are shared. `configure()` loads the camera's Default user set first so pylon Viewer leftovers (test pattern, ROI, LUT) never leak in. Gain via the `Gain` node (dB); temp via `DeviceTemperature` (NaN fallback). Exposures below/above the camera range (min 21 µs on acA1920-155um) are clamped in `snap()` with a warning, and the effective exposure is exposed as `last_exposure_s` (cli records it in metadata/filenames). `close()` is a real close (StopGrabbing + Close) — no wedging like playerone macOS.
- **`configure()` also forces `GainAuto`/`ExposureAuto`/`BlackLevelAuto` = Off and sets a digital black level** so dark frames don't underflow — without it the IMX174's default keeps the read-noise distribution pinned at 0 (97 % of dark pixels at exactly zero, Aug 2026), which censors the dark histogram and destroys σr, σ²dark, and low-signal PTC points. The `BlackLevel` node is 5.4 fixed-point (range 0..31.9375 ≈ 0..511 DN12, i.e. ~16 DN12/unit on the IMX174 — verified: node 31.9375 → 8,160 DN16 dark mean); the DN12 target is `_BLACK_LEVEL_DN12 = 8` (≈ 128 DN16 mean). The resulting mean dark offset must stay < 0.5 % of pixels at zero (EMVA) and is recorded as `black_level_dn12` in metadata.
- **CLI `--exposures` is in milliseconds** (`_parse_exposures_ms`), seconds were the pre-typer convention: `0.001` means 1 µs (clamped to the 21 µs minimum!) — use ms values like `1,10,100`, and note that sub-minimum exposures that clamp to the same effective exposure collide to one filename (silent overwrite).

## Thorlabs backend (TLCamera SDK) — conventions

- `camchar/backends/thorlabs.py` drives Thorlabs scientific cameras through the **official** `thorlabs_tsi_sdk` Python wrapper (vendored at `vendor/thorlabs/py/thorlabs_tsi_sdk`, v0.0.8 — no known ABI bugs, unlike Player One's wrapper; use it as-is). Native DLLs are a curated mono runtime subset in `vendor/thorlabs/lib/` (camera sdk + zelux USB device + hotplug monitor + logger, ~700 KB); the full distribution stays untracked under `/Scientific Camera Interfaces/` (gitignored). Windows x64 only for now. Install ThorCam once for the WinUSB driver.
- The wrapper loads `thorlabs_tsi_camera_sdk.dll` by bare name at `TLCameraSDK()` construction: `vendor/thorlabs/lib` must be on the DLL search path (PATH prepend + `os.add_dll_directory`) *before* any SDK object exists — handled at module import.
- **Frames arrive right-aligned DN12 in uint16** (verified: dark mean == black level ≈ 5 DN12 on LP126MU) and are `<<4` to DN16 in `snap()`, matching basler/playerone. Do not remove the shift.
- **The ROI lower-right coordinate is inclusive** on this family (full frame = `(0, 0, w−1, h−1)`), contradicting the SDK docstring example. `configure()` only rewrites the ROI when the readback doesn't already cover the full sensor.
- **No temperature API exists anywhere in the TLCamera C API**: `sensor_temp_c()` returns NaN and the class sets `has_temperature = False`; `_warmup_sensor` refuses to run thorlabs warmup (exit 1) because thermal stability can't be verified. Don't "fix" by faking a temperature.
- Gain is an integer index (0..480 on LP126MU): `--gain` is int-coerced like playerone; `configure()` records the dB equivalent as `gain_db` and the factory black-level offset as `black_level_dn12` (default 5 on LP126MU — dark frames sit safely above zero, no offset needed unlike Basler). Hot-pixel correction is forced off (neighbor substitution corrupts temporal variance).
- Exposure is integer µs (28 µs .. ~14.7 s on LP126MU), clamped with warning + `last_exposure_s` like basler. `close()` must be a REAL teardown (camera dispose → SDK dispose; Thorlabs warns of crashes on exit otherwise) — the exact opposite of playerone's macOS no-op close.

## Architecture and conventions

- Backend registry: new vendor = implement `CameraBackend` (`camchar/backends/base.py`) in `camchar/backends/<vendor>.py` with `@register("<vendor>")`; registration happens at import (bottom of `camchar/backends/__init__.py`).
- Data layout (gitignored): sequences live under `<root>/<vendor>_<model>_(<sensor>)/{dark,flat}/` (`camchar/io_utils.py:camera_dir_name()`; acquisition `--out` is the root, default `data`). Files are `{dark|flat}_{NNNNN}ms|us_g{gain}.npy` — uint16 stack `(n, h, w)` — plus an append-only `metadata.json` per directory. Naming rule lives in `camchar/io_utils.py:stem_for()` (integer ms >= 1 -> `ms`, else `us`); `analyze.py` reconstructs filenames from metadata via `stem_for`, so the two must stay in sync. `analyze.py:resolve_data_dir()` accepts the root or a camera dir; the legacy `data/dark` layout still works.
- Frames are 12-bit data stored as DN12 << 4 (DN16). Gain math in `camchar/analyze.py`: fit `dV = K_fit*S` on temporal variance with the EMVA Eq. 50 form `σ_y² = σ_y.dark² + K(µ_y − µ_y.dark)` — `S = mean − bias_dn` and `dV = tf_tvar − σ_y.dark²(t_exp)` with the **two-frame Eq. 18 temporal variance as the primary estimator** (`flat['dV']`, drift-robust: adjacent-pair differences reject between-acquisition lamp/drift offsets, the SPECIM degenerate-PTC cause), the dark variance interpolated per exposure from the dark rows (linearly extrapolated outside the dark grid); the N-frame dark-subtracted variance is the cross-check (`flat['dV_nf']`). The regression is zero-intercept (slope-only, `K_fit = Σ(S·dV)/ΣS²`), then `K12 = 16/K_fit` — the gain is the inverse of the slope, not the slope. Points with `dV <= 0` (dark-subtraction noise at the lowest signals) drop out of the fit/plot/per-point check when ≥3 positive points remain, so the three share one selection. R² is the uncentered form (TSS = ΣdV² — the model is through the origin). The free (offset) fit intercept `ptc_intercept_free` is the sanity check: ~0 for a valid PTC, and a large deviation flags PTC curvature (PRNU²·S² super-linearity or dark drift). Clip threshold 65400 DN; default ROI `500:900:750:1150` (only the ROI must be uniformly illuminated). PTC-fit points additionally require `sat_frac <= 0.002` (EMVA §6.6): a point whose mean sits below 65400 can still be majority-pinned, and pinned pixels have no variance — including such points bends the fit negative (seen in the SPECIM bright mid-band). The regression range follows the R4 Linear PTC rule: all points between the minimum value and 70% saturation (`PTC_FIT_SAT_FRAC * mu_sat`, `mu_sat` = largest mean passing the §6.6 test; the cap stays in raw DN, only the fit abscissa is bias-subtracted); points above are excluded (`ptc_capped`/`ptc_sat_70_dn` in the flat dict), and when the data never reaches saturation (fewer than 3 points under the cap) the cap is relaxed so the fit isn't starved. The dark-subtracted variances per flat row are exposed as `flat['dV']`/`flat['dV_nf']` (aligned with `flat['rows']`) so plots and the per-point gain check share the same math.
- **Temporal variance is ddof=1** (`np.var(axis=0, ddof=1)`, EMVA R4 Linear Eq. 65 uses 1/(L−1)); the ddof=0 population estimator is biased low by (N−1)/N — 5% at N=20, which inflated K/σr/NSat-derived values. Spatial variance stays ddof=0 (EMVA spatial sums use 1/(NM); bias <0.01% at 10⁴ px).
- `analyze` cross-checks every primary two-frame statistic with the **N-frame estimator** (the inverse of the historical convention): `roi_stats()`/`_band_roi_stats()` compute both, but the fits consume the Eq. 18 two-frame temporal variance and the Eq. 32 two-frame spatial covariance (averaged over consecutive frame pairs) as primary — `K`, `σr`, `dV`, `prnu_pct` — while the N-frame values feed the cross-check keys (`K12_nf`, `sigma_r_nf_*`, `dV_nf`, `prnu_nf_pct`). The `nf` columns/lines must agree with the two-frame values to <~1% when the source is stationary; a systematic gap signals drift between acquisitions (the SPECIM case) — don't explain it away.
- **EMVA citations follow R4 *Linear* numbering** (`docs/EMVA1288Linear_4.0Release.pdf` is the reference document; the General companion PDF in `docs/` numbers the same equations differently — don't mix them). PTC gain K is core Linear methodology (§2.4/§6.6). σr is the Eq. 30 fit offset of tvar-vs-exposure (two-frame tvar as primary), reported alongside an Eq. 53 quantization-corrected value (step = 16 DN16 → σq² = 21.3 DN16², ~14% of the dark variance — the corrected value is the physical one). The Eq. 30 variance-fit slope is a second dark-current estimate; a large mean/variance slope mismatch flags dark-current nonuniformity or drift. PRNU1288 (Eq. 67)/DSNU1288 (Eq. 66, reported in DN16) use the §8.1 highpass (7×7 + 11×11 box, 3×3 binomial) at ~50% saturation with the Eq. 36 temporal-residual correction (two-frame tvar) on Eq. 33 L-averaged images (see `emva1288_extras()`); saturation µy.sat per §6.6 (≤0.2% pixels at 65504 DN16); DR per Eq. 28. The SNR plot carries the Eq. 69 total-SNR curve (DSNU1288 in e⁻ = DN16·K12/16 + PRNU1288 + σq²/K² on top of the temporal terms) and per-exposure measured total-SNR points (`snr_total_model()`/`snr_total_measured()` in `analyze.py`, consumed by both the monochrome and per-band SNR plots). Photon-unit quantities and η need a calibrated photodiode (§6.4) — outside this tool.
- `load_sequence()` dedupes metadata entries by (exposure, gain): `metadata.json` is append-only and accumulates duplicates across runs; the npy files are the ground truth.
- **SPECIM IQ path** (`analyze --data <specim root>`): `specim.py` discovers `<root>/dark frames|flat-field frames/<N> ms/<ID>/capture/<ID>.hdr` (spaces in names are load-bearing; exposure = `<N> ms` folder, cross-checked against header `tint`; cubes = headers with all-digit stems — `DARKREF_*`/`WHITEREF_*` are 512×1×204 stored-calibration slabs, never used). Raw 12-bit DN is shifted `<<4` to DN16 at load so every DN16 constant and fit is shared with the playerone path. `band_analyze.py` treats each of the 204 bands as an independent camera via the same pure fits (`fit_dark_stats()`/`fit_flat_stats()`/`emva_extras_core()` in `analyze.py` — the printing wrappers `analyze_dark`/`analyze_flats`/`emva1288_extras` and the per-band code must both consume these; don't duplicate the math). One pass per exposure loads cubes ROI-cropped: pixels come from `specim.read_roi_bil()` (mmap of the BIL raw as (lines, bands, samples) + one strided slice — **never use `envi.read_subimage()`, its per-pixel seek/fromfile loop is ~400x slower and was the 15-25 min full-run bottleneck**; `envi.open` is used for header metadata only, and the `img[:, r0:r1, c0:c1]` slice form still trips a spectral BIL indexing bug). Per-band N-frame/two-frame stats are batched over the band axis in `_band_roi_stats()` (one float64 conversion; values match `roi_stats()` exactly). Outputs: `outputs/SPECIM_IQ/band_parameters.csv` + per-band plot variants (`*_bands.png`) + parameters-vs-wavelength summary; `--bands N` selects N equispaced curve bands (default 5). Bands with <3 usable flat points are reported `skipped`, not errors.
- `uv.lock` is intentionally gitignored; don't commit it. `data/` holds large acquisition sequences — never commit it.
- SPECIM per-band statuses: bands with <3 usable flat points are `skipped` (not errors); bands with a non-positive V-vs-S fit slope are `degenerate PTC` — with the two-frame primary, the between-acquisition drift that used to bend the N-frame variance no longer affects the fit, so a degenerate band now signals saturation-collapsed variance and/or per-acquisition shutter/lamp jumps (check the data, don't hide it). The N-frame columns (`K12_nf`, `dV_nf`) remain the drift indicator: a systematic two-frame-vs-N-frame gap flags between-acquisition non-stationarity.
